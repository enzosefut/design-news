**AI 辅助设计日报 · 11 月 23 日**

**1. Figma Workflow Lab：用 Specs 与 Figma agent 把 PRD、设计稿和 code layers 收成实施计划，再经 MCP 交给 Codex**
周五上午日报之后，Figma 官方（Specs 技术负责人 Johnny Dallas）在 11 月 20 日发布了一篇 Workflow Lab，演示如何把散落的上下文收成编码代理能执行的计划。Specs 本身从 10 月 15 日起已在开放测试，帮助文档写明目前面向 Starter、Professional、Education、Organization、Enterprise 全套餐；在 Design / FigJam 工具栏点 Spec 或按 D 即可插入，也可打开 figma.com/spec/new。手动撰写不消耗 AI credits，调用 agent 才会扣额度。

演示里的产品是虚构市集应用 Pickup 的配送功能。需求写了先在一座城市试点，但没定是哪座。工程师通过 Hex 连接器让 Figma agent 查用量，agent 写出带城市对比表的 spec，并生成前四座城市的地图 code layers；团队据此选定印度班加罗尔。接着工程师把技术 spec、FigJam 里的配送流程图、带标注的终稿、可交互的班加罗尔地图 code layer，以及设计系统新组件和用法说明都放到画布上，选中后调用团队预先配置的 `build-implementation-plan` skill。agent 生成一份新的实施计划 spec：功能长什么样、怎么表现、设计系统、测试与可观测性、上线安排，以及带回溯引用的任务表。

工程师先审核，再对一处错误留言，并提示 agent：`Read my comment and reply to it with a solution.` agent 会回一条带修改建议的评论。另一处需要设计师拍板，工程师在评论里 @ 对方，设计师收到通知后进文件实时改。最后复制这条 spec 的链接，在 Codex 里贴上并提示 `Implement this feature`。经 Figma MCP，Codex 能顺着这一条链接读到计划本身，以及计划引用的标注设计稿、code layers 和设计系统组件。帮助文档还写明，接上 Figma MCP 的编码代理可以用 `figma-spec` skill 读写独立或内嵌的 Spec。整段流程里，Figma agent 负责取数、整理和起草计划，并不直接写生产代码。
